# External Skill Dedup Decision — Phase 2c

Decision on whether to **promote** external repo skills (9arm, DDC) to live/loadable
skills, or **catalog only**. Companion to the 25 catalog notes in this folder and to
`skill_registry_topology.md` (shared manuals).

## Decision (CLC)

**Promote NONE now. Catalog only.** Both repos' relevant skills are either duplicates of
already-installed skills or depend on infrastructure this environment does not have.

## Evidence

**In-house QS surface is narrow.** The only live estimating capability is
`edge-furniture-pricing` (Thai interior built-in furniture: A/B/C pricing, rate card,
V4 markup, man-day schedule, procurement audit). A search for any broader QS/estimator
engine returned nothing — there is **no general-construction QS system** here.

**DDC QS-cluster depends on missing infrastructure.** The CWICR skills assume the CWICR
cost database (55,719 work items); the BIM/IFC skills assume Revit/IFC models. Neither
exists in this environment. Registering them would create non-functional shelfware that
cannot run — the exact failure mode the skill-registry plan was built to avoid.

**9arm is mostly already installed.** Of 4 skills, `debug-mantra`, `scrutinize`,
`post-mortem` are already live skills here; only `management-talk` is new (low priority).

## Conditions to revisit (when promotion would make sense)

Promote a subset **only if** the system later acquires: (a) the CWICR cost database (or an
equivalent rate DB), and/or (b) a BIM/IFC ingestion pipeline, **and** the business expands
beyond interior furniture into general construction estimating. At that point the strongest
candidates are `cwicr-cost-calculator`, `cwicr-takeoff-helper`, and `cwicr-risk-calculator`
(the latter could enhance edge-furniture-pricing's flat 50% safety factor with probabilistic
contingency even within the furniture domain — the one near-term promotion worth re-evaluating).
